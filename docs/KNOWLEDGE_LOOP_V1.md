# AI OBEC Knowledge Loop V1.1
## รอบดำเนินงาน
1. อ่าน MASTER_PLAN.md และ QA_STANDARD.md สดจาก main ก่อนเริ่ม ตรวจสอบสถานะใน Drive ปลายทาง
2. สำรวจต้นทางแบบ recursive ทุกหน้า ตรวจ file ID, path, MIME, modified time และ checksum เมื่อมี; เปรียบเทียบทะเบียนรอบก่อนใน Drive ภายใน
3. คัดลอกไฟล์ใหม่/ฉบับเปลี่ยนไปยังหมวดที่ตรงกันโดยใช้ source ID + revision/modified time เป็นกุญแจ ป้องกันซ้ำ ไม่ลบต้นทางหรือทับสำเนาเดิม; กรณีไฟล์หายให้บันทึก ไม่ลบอัตโนมัติ
4. อ่านหลักฐานสด เลือกงานค้างอันดับแรกหรือเอกสารเปลี่ยนแปลงที่มีผลต่อแนวทาง ทำหนึ่งชุดที่มีคุณภาพต่อรอบ หากอ่านไม่ได้บันทึก blocked ไม่เดา
5. สังเคราะห์: ข้อเท็จจริงพร้อมชื่อไฟล์/หน้า/หัวข้อ, ความคลาดเคลื่อน, ข้อเสนอ, ขั้นตอนปฏิบัติ, ตัวชี้วัด, ผู้รับผิดชอบตามบทบาท, ความเสี่ยง และคำถามรอยืนยัน
6. ตรวจ QA ก่อนเผยแพร่ภายใน Drive; สร้างเอกสารฉบับใหม่เมื่อเนื้อหาเปลี่ยนหรือมีงานใหม่เท่านั้น ตั้งชื่อ YYYY-MM-DD_topic_vNN; เอกสารผลผลิตที่เป็น PDF ทุกฉบับต้องอัปโหลดเข้า Google Drive ปลายทางของโครงการในหมวดที่ตรงกับงาน ตรวจชื่อซ้ำก่อนอัปโหลด ตรวจรูปแบบและอ่านกลับจาก Drive พร้อมยืนยันลิงก์จริง ไม่ถือว่าการแนบ PDF ในแชทหรือเก็บใน sandbox เป็นการส่งมอบ หากอัปโหลดหรืออ่านกลับไม่ได้ให้รายงาน PARTIAL/BLOCKED และบันทึกงานส่งมอบค้างไว้ ห้ามทำไฟล์ซ้ำเมื่อไม่มีงานใหม่
7. อัปเดตทะเบียนหลักฐานและ backlog ภายใน Drive พร้อม log รอบวันที่และผล PASS/PARTIAL/BLOCKED/NO_CHANGE; GitHub บันทึกเฉพาะสถานะภาพรวมที่ไม่เผยข้อมูลภายในและเฉพาะเมื่อมีความเปลี่ยนแปลง
8. แจ้งผู้ใช้: งานที่ทำจริง ลิงก์ผลส่งมอบ งานค้าง ความเสี่ยง และรายการถัดไป

## กติกา
ไม่แก้ไขต้นทาง ไม่เปลี่ยนสิทธิ์แชร์ ไม่อัปโหลดข้อมูลบุคคล ข้อสอบภายใน อีเมล ลิงก์ Drive ภายใน หรือรายละเอียดเอกสารที่ไม่ผ่านอนุญาตสู่ repo สาธารณะ ไม่สมัครบริการเสียเงินหรือใช้ API ที่ก่อค่าใช้จ่ายโดยไม่ได้รับอนุญาต
เมื่อ connector ใช้ไม่ได้ ให้บันทึก blocker และหยุดการเขียนที่ต้องอาศัยหลักฐานนั้น
เมื่อครบ backlog ให้ตรวจการเปลี่ยนแปลงและช่องว่างต่อ ไม่สร้างรายงานซ้ำทุกวัน
