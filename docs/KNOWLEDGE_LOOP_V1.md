# AI OBEC Knowledge Loop V1.4
## รอบดำเนินงาน
1. อ่าน MASTER_PLAN.md และ QA_STANDARD.md สดจาก main ก่อนเริ่ม ตรวจสอบสถานะใน Drive ปลายทาง
2. สำรวจต้นทางแบบ recursive ทุกหน้า ตรวจ file ID, path, MIME, modified time และ checksum เมื่อมี; เปรียบเทียบทะเบียนรอบก่อนใน Drive ภายใน
3. คัดลอกไฟล์ใหม่/ฉบับเปลี่ยนไปยังหมวดที่ตรงกันโดยใช้ source ID + revision/modified time เป็นกุญแจ ป้องกันซ้ำ ไม่ลบต้นทางหรือทับสำเนาเดิม; กรณีไฟล์หายให้บันทึก ไม่ลบอัตโนมัติ
4. อ่านหลักฐานสด เลือกงานค้างอันดับแรกหรือเอกสารเปลี่ยนแปลงที่มีผลต่อแนวทาง ทำหนึ่งชุดที่มีคุณภาพต่อรอบ หากอ่านไม่ได้บันทึก blocked ไม่เดา
5. สังเคราะห์: ข้อเท็จจริงพร้อมชื่อไฟล์/หน้า/หัวข้อ, ความคลาดเคลื่อน, ข้อเสนอ, ขั้นตอนปฏิบัติ, ตัวชี้วัด, ผู้รับผิดชอบตามบทบาท, ความเสี่ยง และคำถามรอยืนยัน
6. ตรวจ QA ก่อนเผยแพร่ภายใน Drive; สร้างเอกสารฉบับใหม่เมื่อเนื้อหาเปลี่ยนหรือมีงานใหม่เท่านั้น ตั้งชื่อ YYYY-MM-DD_topic_vNN; เอกสารผลผลิตที่เป็น PDF ทุกฉบับต้องอัปโหลดเข้า Google Drive ปลายทางของโครงการในหมวดที่ตรงกับงาน ตรวจชื่อซ้ำก่อนอัปโหลด ตรวจรูปแบบและอ่านกลับจาก Drive พร้อมยืนยันลิงก์จริง ไม่ถือว่าการแนบ PDF ในแชทหรือเก็บใน sandbox เป็นการส่งมอบ หากอัปโหลดหรืออ่านกลับไม่ได้ให้รายงาน PARTIAL/BLOCKED และบันทึกงานส่งมอบค้างไว้ ห้ามทำไฟล์ซ้ำเมื่อไม่มีงานใหม่
7. อัปเดตทะเบียนหลักฐานและ backlog ภายใน Drive พร้อม log รอบวันที่และผล PASS/PARTIAL/BLOCKED/NO_CHANGE; GitHub บันทึกเฉพาะสถานะภาพรวมที่ไม่เผยข้อมูลภายในและเฉพาะเมื่อมีความเปลี่ยนแปลง
8. แจ้งผู้ใช้: งานที่ทำจริง ลิงก์ผลส่งมอบ งานค้าง ความเสี่ยง และรายการถัดไป

## กติกา
ไม่แก้ไขต้นทาง ไม่เปลี่ยนสิทธิ์แชร์ ไม่อัปโหลดข้อมูลบุคคล ข้อสอบภายใน อีเมล ลิงก์ Drive ภายใน หรือรายละเอียดเอกสารที่ไม่ผ่านอนุญาตสู่ repo สาธารณะ ไม่สมัครบริการเสียเงินหรือใช้ API ที่ก่อค่าใช้จ่ายโดยไม่ได้รับอนุญาต
เมื่อ connector ใช้ไม่ได้ ให้บันทึก blocker และหยุดการเขียนที่ต้องอาศัยหลักฐานนั้น
เมื่อครบ backlog ให้ตรวจการเปลี่ยนแปลงและช่องว่างต่อ ไม่สร้างรายงานซ้ำทุกวัน

## V1.3 — สื่อสองแบบต่อหัวข้อ
ทุกหัวข้อสื่อ (panel_id) ต้องสร้าง Infographic A4 อย่างน้อย 2 แบบ (A/B) ใช้สาระและข้อความหลักจาก JSON/MD เดียวกัน แต่ต่างกันชัดเจนด้านองค์ประกอบภาพและการจัดวาง ตรวจ QA แยกแต่ละแบบ อัปโหลดทั้งสองแบบที่ผ่าน QA เข้า Drive ปลายทางทันทีโดยไม่ต้องรอผู้ใช้เลือก ตั้งชื่อ YYYY-MM-DD_topic_vNN_infographic_NN_A.png และ _B.png (เพิ่มเติม C เป็นต้นเมื่อจำเป็น) บันทึก variant_id, QA, ลิงก์ Drive และสถานะการเลือกใน log; ผู้ใช้เลือกภายหลังได้ เก็บทั้งสองแบบ ไม่ลบหรือทับรุ่นเดิม หากแบบใดไม่ผ่านให้แก้หรือระบุ PARTIAL ไม่ถือว่าส่งมอบครบ และไม่เปลี่ยนเวลา automation หรือผลิต PDF ซ้ำ

## V1.4 — สื่อ A4 และ 1:1 (27 พฤศจิกายน 2569)
ขยาย V1.3: ทุก panel_id ที่เหมาะสำหรับสื่อ ให้ผลิต A4 แนวตั้ง A/B และสี่เหลี่ยม 1:1 A/B (รวมอย่างน้อย 4 ภาพต่อหัวข้อ) จาก JSON/MD เดียวกัน ปรับการจัดวางตามสัดส่วน ไม่ครอปจนเนื้อหาหาย; 1:1 เป้าหมายอย่างน้อย 1080×1080 px สำหรับมือถือ/สื่อออนไลน์ ส่วน A4 คงเกณฑ์พิมพ์ 2480×3508 px ที่ 300 dpi หรือเทียบเท่า. ใช้ธีมร่วม แบบ A การ์ตูนให้ความรู้ แบบ B วิชาการสมัยใหม่. เพิ่ม aspect_ratio, variant_id, panel_id, source_version, media_revision, dimensions, QA และ delivery_status ในทะเบียน; ตั้งชื่อ YYYY-MM-DD_topic_vNN_infographic_NN_A4_A.png / _A4_B.png / _SQ_A.png / _SQ_B.png. เก็บไฟล์เดิมและนับ A4 เดิมที่ตรวจแล้วโดยไม่ผลิตซ้ำ; แบ่งชุดสร้างตามขีดจำกัดเครื่องมือ ไม่รับประกัน 10 ภาพต่อคำขอ ไม่ใช้บริการเสียเงินเพิ่ม. ตรวจข้อความไทย ความถูกต้อง การอ่านบนมือถือ ขนาดจริง สิทธิ์ และอ่านกลับจาก Drive แยกทุกภาพ; เก็บ A4 และ 1:1 แยกหมวดหรือแยกด้วยชื่อไฟล์ในหมวดงานเดิม ไม่เปลี่ยนสิทธิ์แชร์. หากเครื่องมือไม่พร้อมหรือภาพไม่ถึงเกณฑ์ ให้บันทึก PARTIAL/MEDIA_PENDING และเติมคิวสื่อภายหลังโดยไม่ผลิต PDF ซ้ำหรือเปลี่ยนคิววิชาการ D2/เวลา automation เดิม. การเผยแพร่ภายนอกต้องได้รับอนุญาต.

## Public activity reporting V1.0 (28 พฤศจิกายน 2569) — สถานีทำงานจริง
ใช้กับ Knowledge Loop เดิมและรอบทำงานจริงที่ได้รับอนุญาต ไม่เปลี่ยนตาราง 08:00 ไม่สร้างรอบใหม่ ไม่ถือเป็นระบบรับงาน/ล็อกงานหรืออนุมัติผล และไม่ข้ามขั้นตอน H3–H5. การอ่านแหล่งหลักฐาน/การเลือกงาน/QA/ส่งมอบยังใช้กติกาข้างต้นทั้งหมด. ห้ามนำข้อมูลจาก TEST-* หรือ Apps Script sandbox มาแสดงเป็นงานจริง.

ช่องรายงานสาธารณะ: `hub/activity.json` (main), schema_version 1, mode REPORTED_ACTIVITY. ดูตัวตรวจรูปแบบและตัวอย่างทดสอบใน `hub/activity.js`. หน้า Studio V0.5 อ่านไฟล์นี้เป็นระยะ ไม่ใช่ WebSocket หรือ live presence. แยกจาก snapshot สรุป `hub/status.json` และทะเบียนภายในโดยเด็ดขาด.
- ก่อนเผยแพร่ RUNNING: ต้องเป็นงานจริงที่เริ่มทำแล้ว มีหลักฐานการเริ่มงานในรอบปัจจุบันและการเลือกงานตาม backlog ที่อ่านสด; บันทึก run ID ภายใน เวลา UTC งาน ขั้นตอน และหลักฐานที่ตรวจใน log ภายในตามหมวดเดิมก่อนเผยแพร่. ไม่เริ่มงานเพียงเพื่อเปิดไฟตัวละคร. ห้ามรายงานจากกำหนดเวลา 08:00 เพียงอย่างเดียว หรืออนุมานจากสถานะ QUEUED/PENDING_REVIEW.
- เผยแพร่เมื่อมีความเปลี่ยนแปลงขั้นตอนที่ทำจริง: EVIDENCE (อ่านหลักฐาน), DESIGN (ออกแบบ), PRODUCE_KNOWLEDGE (ผลิตองค์ความรู้), PRODUCE_MEDIA (ผลิตสื่อ), QA (ตรวจคุณภาพ), DELIVERY (ตรวจส่งมอบ). ไม่กำหนดเวลาในอนาคตหรือกรอกผลสำเร็จล่วงหน้า. รายงาน RUNNING ต้องมี reported_at เป็นเวลาจริง ISO 8601 UTC และ expires_at หลัง reported_at ไม่เกิน 15 นาที; ต่ออายุเฉพาะเมื่อยังทำขั้นตอนนั้นจริงและมีหลักฐานที่ตรวจได้. ไม่ต่ออายุจากตัวจับเวลาหน้าเว็บ.
- ฟิลด์อนุญาตเท่านั้น: schema_version, mode, state, job, phase, reported_at, expires_at, last_completed. job เป็นรหัสกลุ่มงานสาธารณะจาก allowlist ใน activity.js; สายสื่อใช้ -MEDIA. last_completed เป็น null หรือ {job,date,result:"DELIVERED_INTERNAL"} จากการส่งมอบภายในที่ตรวจอ่านกลับแล้ว. ไม่ใช้ชื่อบุคคล ชื่อไฟล์ภายใน URL/ID ของ Drive run ID ภายใน lease token ข้อสอบ ข้อมูลดิบ หรือข้อความอิสระใด ๆ. หากเป็นงานย่อยนอก allowlist ไม่เผยแพร่โดยเดารหัส.
- ก่อนเขียนอ่าน activity.json สดและตรวจไม่ให้ทับรายงาน RUNNING ที่ยังไม่หมดอายุจากอีกรอบ; ใช้ SHA ที่อ่านล่าสุดในการ update_file, ไม่ force push, ถ้าขัดแย้งให้งดรายงานและบันทึกใน log ภายใน. ไม่ใช้ช่องนี้แทนการควบคุม concurrency. ตรวจ JSON ด้วยกติกา activityView และอ่านกลับจาก main ทุกครั้ง. หากเขียน/อ่านกลับไม่ได้ ให้ระบุ reporting PARTIAL แยกจาก QA ผลผลิตจริง; ห้ามสร้างหลักฐานเทียมหรือผลิตซ้ำ.
- เมื่อจบจริงให้รายงาน state DELIVERED_INTERNAL / PARTIAL / BLOCKED / NO_CHANGE ตามผลจริงหลัง log/หลักฐานอ่านกลับ; phase และ expires_at เป็น null; job และ reported_at ต้องตรงงานที่ทำ; last_completed เปลี่ยนเฉพาะงานส่งมอบภายในที่ยืนยันแล้ว. หากไม่มีงานที่ยืนยันได้ให้ใช้ NO_CONFIRMED_ACTIVITY โดย job/phase/reported_at/expires_at เป็น null และเก็บ last_completed เดิม. อย่าล้างรายงานจากรอบอื่น. ถ้ารอบถูกตัดกลางคัน รายงานจะหมดอายุเองใน UI และดับไฟ; ไม่ถือว่ารอบเสร็จ.
- H3/H4 ยังไม่เปิดการรับงานจริงผ่าน Apps Script หรืออนุมัติจากเว็บ. การรายงานนี้ใช้เครื่องมือ GitHub ที่มีอยู่และหลักฐานภายในเดิมเท่านั้น. ผู้ปฏิบัติงานที่อ่านมาตรฐานสดต้องปฏิบัติตามส่วนนี้; หากเครื่องมือไม่พร้อมให้ทำงานวิชาการตามเกณฑ์เดิมและรายงานข้อจำกัด. ไม่เปลี่ยนสิทธิ์แชร์ ไม่เพิ่มบริการเสียเงิน.
